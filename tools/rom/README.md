# tools/rom: Pippin boot ROM region map and disassembler

Static analysis only. The tools read the ROM image as data; no ROM code is executed.

## Setup (once)

```sh
sh tools/rom/setup.sh
```

This creates everything under `scratch/` (git-ignored):

| What | Where | Why |
|---|---|---|
| Python venv with `capstone==5.0.9` (and `tbxi==0.13`, optional, for cross-checks) | `scratch/venv` | Capstone is the 68K/PPC disassembler engine |
| OpenBIOS fcode-utils @ `6e563ee` (GPL-2.0), `detok` built | `scratch/third_party/fcode-utils` | detokenises the Open Firmware FCode images |
| multiversal @ `55b83c5` (MIT, Wolfgang Thaller) | `scratch/third_party/multiversal` | only needed to regenerate `data/traps.tsv` and `data/lowmem.tsv` |

Without `detok` the FCode images are written as hex dumps instead.

## Getting the listings without running anything

The listings are committed as one archive, `disasm/disasm.tar.xz` (about 7.7 MB; 108 MB unpacked). The unpacked folders `disasm/kinka-1.0/` and `disasm/kinka-dev/` are git-ignored. The 1.0-vs-Dev report `disasm/diff-1.0-vs-dev.md` stays plain text.

```sh
python3 tools/rom/pack.py unpack    # disasm/disasm.tar.xz -> disasm/kinka-1.0/, disasm/kinka-dev/
python3 tools/rom/pack.py pack      # rebuild the archive from those folders
```

`pack` is reproducible: the same listings give a byte-identical archive, so re-packing unchanged output leaves nothing to commit. Both ROMs share one archive so xz can compress the nearly identical listings against each other (two separate archives would be 12.4 MB). `disassemble.sh` (no arguments) repacks automatically.

## Run

```sh
tools/rom/disassemble.sh                  # both ROMs in ROMs/ -> disasm/kinka-1.0, disasm/kinka-dev, disasm/diff-1.0-vs-dev.md
tools/rom/disassemble.sh <rom> [outdir]   # one ROM; outdir defaults to disasm/<rom file stem>
```

Or call the Python entry point directly (`-I` is safe: `run.py` adds its own directory to `sys.path`):

```sh
scratch/venv/bin/python3 -I tools/rom/run.py <rom> <outdir> [--label NAME] [--detok PATH]
scratch/venv/bin/python3 -I tools/rom/run.py --diff <romA> <romB> <out.md> [--labels A B]
```

One ROM takes about 5 s. The diff takes about 90 s, mostly difflib over the 68K listings.

## Output (per ROM)

| File | Content |
|---|---|
| `index.md` | Landmark checks, coverage by kind, and every region (offset, end, size, kind, ISA, file, SHA-1 prefix). The rows are contiguous and cover all 4 MB. |
| `00_rom_header.txt` | 68K header fields, recomputed checksums, ForeignOS table |
| `m68k_main/*.s` | 68K main code, linear sweep, split into 64 KB-of-ROM files |
| `resources.txt` | ROM resource list: every entry with entry offset/length, data offset, size, type, id, attributes, name, combo |
| `rsrc/<type>_<id>[_name].s` / `.hex.txt` | 68K code resources disassembled; data resources hex-dumped with decoded headers (PICT, snd, vers, STR#, FONT, thng, DRVR, ...) |
| `pef/<resource>/container.txt`, `code_sN.s`, `data_sN.hex.txt` | PEF header, sections, imports, exports, relocations; PPC code with export/TV/glue labels and TOC annotations; raw and unpacked data with symbolic relocations |
| `ppc_exception_table.s`, `nanokernel.s`, `emulator.s`, `emulator_opcode_table.s`, `hwinit/` | PowerPC regions |
| `configinfo.txt`, `blob_directory.txt`, `blobs/` | ConfigInfo fields, the Pippin blob directory, and its blobs |
| `openfirmware/` | XCOFF header, `of_native.s` (PPC, labelled from the Forth headers), `of_words.txt`, `fcode_NN.fth` (detok output) |

## Annotation sources

- A-line trap names and low-memory global names: `data/traps.tsv` and `data/lowmem.tsv`, generated by `gen_tables.py` from multiversal (MIT). Coverage is about 720 traps and 250 globals. Unknown traps are flagged, not guessed. Flag suffixes (`,SYS`, `,CLEAR`, `,ASYNC`, `,IMMED`) are derived from bits 9 and 10 of the trap word.
- PPC SPR names (603 set) and the MMIO map are in `pippinrom/annot.py`. The MMIO map comes from `docs/core-dev/README.md` §1.2, MAME (`taos.cpp`, `bandit.cpp`, `heathrow.cpp`) and DingusPPC (`aspen.h`, `taos.h`).
- Structure formats:
  - 68K header, resource list and ConfigInfo: Elliot Nunn's tbxi field layouts.
  - PEF: Apple, *Mac OS Runtime Architectures*, ch. 8.
  - XCOFF and traceback tables: the AIX format.
  - Pippin-specific structures (blob directory, OF word headers, FCode descriptors): observed in these ROMs. They are described as such in the output.

## Modules

`pippinrom/` contains:

- `rom.py`: header, checksums, resources, ConfigInfo, XCOFF, OF scans
- `pef.py`: PEF
- `analyze.py`: region builder and coverage
- `m68k.py`, `ppc.py`: listings
- `datafmt.py`: hex dumps and decoders
- `emit.py`: file writer
- `landmarks.py`: sanity checks
- `diff.py`: the ROM comparison

## Limits

- 68K code is a linear sweep. Tables and strings inside code areas decode as junk instructions.
- PPC code is also swept linearly. Data islands in the emulator and NanoKernel show up as `.long` or odd instructions.
- Function-level diffs of PPC code use a heuristic for function starts (the word after a `blr`).
- tbxi 0.13 does handle these ROMs: it has a Pippin special case for the bad ConfigInfo checksum, and its resource list matches ours (300 resources). However, its `OpenFW` extract runs past the XCOFF image into the blob area. This tool uses its own parsers.
